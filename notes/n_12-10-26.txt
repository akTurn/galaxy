## 1. The main issues in your current code

Issue 1: Inconsistent relationship queries

`get_outgoing()`, `get_incoming()`, and the default `get_neighbors()` call `_relationships()`, which returns `all_relationships()`.

However, `traverse_current()` and `shortest_path()` use `current_relationships()`.

Your relationship tuples contain both entity types and IDs, but the graph methods match only IDs.

For example, Galaxy has processes, services, applications, databases, and other entity types. Matching both `entity_type` and `entity_id` will make graph queries more precise.

`get_neighbors()` returns `entity_id`, relationship, and direction, but omits the neighbor's `entity_type`.

to:

```
graph.traverse_current("process", "123")graph.get_current_neighbors("process", "123")
```

Your current graph traversal and historical graph traversal will now follow the same composite-identity rule, while still choosing different relationship sets.

from core.correlation.finding import Finding


class CorrelationEngine:
    def __init__(self, store, graph, rules=None):
        self.store = store
        self.graph = graph
        self.rules = list(rules or [])

    def register_rule(self, rule):
        if any(
            existing.rule_id == rule.rule_id
            for existing in self.rules
        ):
            raise ValueError(
                f"Duplicate correlation rule: {rule.rule_id}"
            )

        self.rules.append(rule)

    def run_once(self):
        observations = self.store.all()
        findings = []

        for rule in self.rules:
            rule_findings = rule.evaluate(
                observations,
                self.graph,
            )

            if rule_findings is None:
                raise TypeError(
                    f"Rule {rule.rule_id} returned None; "
                    "expected a list of Finding objects"
                )

            if not isinstance(rule_findings, list):
                raise TypeError(
                    f"Rule {rule.rule_id} must return "
                    "a list of Finding objects"
                )

            for finding in rule_findings:
                if not isinstance(finding, Finding):
                    raise TypeError(
                        f"Rule {rule.rule_id} returned "
                        "an invalid finding"
                    )

            findings.extend(rule_findings)

        return findings

## What we've created

- `finding.py` — standard structure for a detected problem, including severity, affected entities, and evidence.
- `correlation_rule.py` — common interface that every correlation rule must implement.
- `correlation_engine.py` — loads observations from your store, runs registered rules against the observations and `MachineGraph`, and collects findings.
- `rules/` — directory where we will add individual detection rules.

This is the foundation only; it does not detect any issues yet or persist findings. The next implementation step is to add the first real correlation rule and test it against Galaxy's existing observations and typed graph relationships.
