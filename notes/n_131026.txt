In Galaxy, your `FindingStore` creates a SQLite table called `findings`.

## 2. Understand the migration line by line

### Step A: Read the existing column names

```
columns = {    row[1]    for row in self.conn.execute(        "PRAGMA table_info(findings)"    ).fetchall()}
```

Let's break this down.

1\. `PRAGMA table_info(findings)`

This is a SQLite command that asks:

> What columns currently exist in the `findings` table?

For example, SQLite might return rows similar to these:

```
(0, 'finding_id', 'TEXT', 1, None, 1)
(1, 'rule_id', 'TEXT', 1, None, 0)
(2, 'first_seen', 'TEXT', 1, None, 0)
(3, 'last_seen', 'TEXT', 1, None, 0)
(4, 'status', 'TEXT', 1, "'active'", 0)
```

Each row contains information about one column. The second item, `row[1]`, is the column's name.

For example:

```
row = (0, 'finding_id', 'TEXT', 1, None, 1)print(row[1])
```

Output:

```
finding_id
```

2\. `.fetchall()`

```
self.conn.execute(    "PRAGMA table_info(findings)").fetchall()
```

- `execute()` runs the SQLite command.
- `fetchall()` retrieves all the rows returned by that command.

3\. `{row[1] for row in ...}`

This is called a set comprehension. It collects the second item from every row into a set.

The resulting `columns` variable looks like this:

```
{    "finding_id",    "rule_id",    "title",    "first_seen",    "last_seen",    "status",    "resolved_at"}
```

Your actual set depends on the columns in your database.

Why use a set? Because it makes checking whether a column exists straightforward.

### Step B: Check whether the new column is missing

```
if "occurrence_count" not in columns:
```

This asks:

> Is `occurrence_count` absent from the existing table?

- If the column exists, the condition is `False`. Nothing is changed.
- If the column is missing, the condition is `True`. The code enters the `if` block.

This makes the migration safe to run again without trying to add the same column repeatedly.

### Step C: Add the missing column

```
self.conn.execute("""    ALTER TABLE findings    ADD COLUMN occurrence_count INTEGER NOT NULL DEFAULT 1""")
```

Here is what each part means:

| SQL                           | Meaning                                     |
| ----------------------------- | ------------------------------------------- |
| `ALTER TABLE findings`        | Modify the existing table.                  |
| `ADD COLUMN occurrence_count` | Add a new column named `occurrence_count`.  |
| `INTEGER`                     | Store an integer, such as `1`, `2`, or `3`. |
| `NOT NULL`                    | Do not allow the value to be `NULL`.        |
| `DEFAULT 1`                   | Use `1` when no value is provided.          |

Why `DEFAULT 1`?

Imagine your database already contains 20 findings. When SQLite adds this column, existing records need a valid value. The default of `1` gives those records an initial occurrence count.

It also means a new finding can start with a count of `1` when the insert statement doesn't explicitly supply another value.

### Step D: Save the database changes

```
self.conn.commit()
```

`commit()` confirms the database changes made in the current transaction.

Without committing, changes may not be permanently saved as expected, depending on the connection and transaction behavior.

In your code, this commit follows both the table creation and the conditional migration.

## 3. Where does this code belong?

Inside `core/storage/finding_store.py`, put the migration in `_create_table()`, immediately after the `CREATE TABLE IF NOT EXISTS findings` statement has executed.

The method should follow this structure:

```
def _create_table(self):    self.conn.execute("""        CREATE TABLE IF NOT EXISTS findings (            finding_id TEXT PRIMARY KEY,            rule_id TEXT NOT NULL,            title TEXT NOT NULL,            description TEXT NOT NULL,            severity TEXT NOT NULL,            affected_entities TEXT NOT NULL,            evidence TEXT NOT NULL,            first_seen TEXT NOT NULL,            last_seen TEXT NOT NULL,            occurrence_count INTEGER NOT NULL DEFAULT 1,            status TEXT NOT NULL DEFAULT 'active',            resolved_at TEXT        )    """)    columns = {        row[1]        for row in self.conn.execute(            "PRAGMA table_info(findings)"        ).fetchall()    }    if "occurrence_count" not in columns:        self.conn.execute("""            ALTER TABLE findings            ADD COLUMN occurrence_count INTEGER NOT NULL DEFAULT 1        """)    self.conn.commit()
```

Notice that the new table definition already includes `occurrence_count`. The migration handles the other case: a table that was created before you introduced that column.

## 4. What happens when Galaxy starts?

1. Galaxy opens `galaxy.db` and calls `_create_table()`.
2. SQLite creates `findings` if the table doesn't exist.
3. Galaxy reads the table's column names using `PRAGMA table_info(findings)`.
4. If `occurrence_count` is missing, Galaxy adds it. Otherwise, it leaves the table unchanged.
5. Galaxy commits the changes and continues running.

The key concept: A database schema migration changes the structure of an existing database while preserving its existing records. Your code performs a small, conditional migration whenever `FindingStore` initializes.
