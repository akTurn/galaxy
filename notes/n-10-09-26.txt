```text
      │
      │ receives connection from
      ▼
192.168.1.20:54321
```

That's where the architecture gets interesting.

---

# 2. First concept: Network Interface

An **interface** is basically a network connection point on your machine.

Run this on your Linux VM:

```bash
ip addr
```

You'll probably see things such as:

```text
lo
eth0
ens33
enp0s3
```

depending on your VM configuration.

### `lo`

`lo` means **loopback**.

It represents the computer talking to itself.

For example:

```text
127.0.0.1
```

means:

```text
this machine
```

### `eth0` / `ens33` / `enp0s3`

These are physical or virtual network interfaces.

Your VM might have something like:

```text
eth0
    IPv4: 192.168.x.x
```

This is how the VM communicates with other machines.

---

# 3. Second concept: IP address

An IP address identifies a network location.

For example:

```text
192.168.1.50
```

or:

```text
10.0.0.15
```

There are two major versions:

```text
IPv4
192.168.1.50

IPv6
fe80::1234:abcd:5678
```

For our first implementation, we'll collect both.

---

# 4. Third concept: Port

This is extremely important for Galaxy.

An IP address identifies a machine/network location.

A **port identifies a communication endpoint on that machine.**

Think:

```text
IP address = building address

Port = apartment/room number
```

For example:

```text
192.168.1.50:8080
```

means:

```text
machine = 192.168.1.50
port    = 8080
```

Common examples:

```text
22    SSH
80    HTTP
443   HTTPS
5432  PostgreSQL
3306  MySQL
```

Galaxy will eventually discover these rather than assuming them.

---

# 5. Fourth concept: Listening port

A program can **listen** for incoming network connections.

For example:

```text
Python Flask
      │
      ▼
127.0.0.1:5000
      │
      └── LISTENING
```

This means:

> "There is a program waiting for somebody to connect to port 5000."

This is extremely useful for Galaxy because we eventually want:

```text
Port 5000
    ↓
Which process owns it?
    ↓
Python
    ↓
Which application?
    ↓
Galaxy application understanding
```

---

# 6. Fifth concept: Network connection

A connection is an actual communication relationship.

For example:

```text
192.168.1.50:5000
        │
        │ TCP
        ▼
192.168.1.100:42135
```

There are two sides:

```text
Local side
192.168.1.50:5000

Remote side
192.168.1.100:42135
```

And the connection has a state.

For TCP, examples include:

```text
LISTEN
ESTABLISHED
TIME_WAIT
CLOSE_WAIT
```

We don't need to implement every network concept at once.

# 7. Our first Network Intelligence milestone

Let's divide Network Intelligence into smaller steps.

### 10A — Network interfaces

Galaxy learns:

```text

├── name
├── MAC address
├── state

```

### 10B — Listening ports

Galaxy learns:

```text
Port
├── protocol
├── local address
├── local port
└── status
```

### 10C — Network connections

Galaxy learns:

```text
Connection
├── protocol
├── local address
├── local port
├── remote address
├── remote port
└── state
```

### 10D — Process → Network

Then the important relationship:

```text
Process
   │
   └── owns/uses
          ↓
       Port
          ↓
      Connection
          ↓
       Endpoint
```

We'll do these **one at a time**.
