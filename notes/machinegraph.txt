# 2. What is the job of `MachineGraph`?

We now introduce:

```text
core/graph/machine_graph.py
```

Its job is simple:

> Given an entity, find what is connected to it.

It should NOT:

* collect processes
* collect network information
* collect services
* save observations
* create relationships
* understand systemd
* understand Linux

Those jobs already belong elsewhere.

`MachineGraph` only **navigates relationships**.

# 11. Step 7 — Add traversal

This is the important part.

We want Galaxy to be able to say:

> Start at this entity and show me everything connected within 3 levels.

Add:

```python
    def traverse(self, root_entity_id, max_depth=3):

        visited = set()

        def walk(entity_id, depth):

            if depth > max_depth:
                return None

            if entity_id in visited:
                return None

            visited.add(entity_id)

            node = {
                "entity_id": entity_id,
                "neighbors": [],
            }

            neighbors = self.get_neighbors(entity_id)

            for neighbor in neighbors:

                child = walk(
                    neighbor["entity_id"],
                    depth + 1,
                )

                if child is None:
                    continue

                node["neighbors"].append({
                    "relationship": neighbor["relationship"],
                    "direction": neighbor["direction"],
                    "node": child,
                })

            return node

        return walk(root_entity_id, 0)
```

This is very similar to your existing `NetworkGraph.traverse()`.

The difference is that now it belongs to the **general machine graph**.

---

# 12. Why do we need `visited`?

This is extremely important.

Graphs can contain cycles.

Imagine:

```text
A -> B
B -> C
C -> A
```

Without:

```python
visited = set()
```

Galaxy could do:

```text
A
 ↓
B
 ↓
C
 ↓
A
 ↓
B
 ↓
C
...
```

forever.

So:

```python
if entity_id in visited:
    return None
```

means:

> We have already visited this entity. Don't follow it again.

This is standard graph traversal.

# 13. Your complete `MachineGraph`

At this stage, make the file:

```python
from core.storage.sqlite_store import SQLiteStore


class MachineGraph:

    def __init__(self, store: SQLiteStore):
        self.store = store

    def _relationships(self):

        return self.store.all_relationships()

    def get_outgoing(self, entity_id):

        relationships = self._relationships()

        results = []

        for relationship in relationships:

            source_id = relationship[1]

            if source_id == entity_id:
                results.append(relationship)

        return results

    def get_incoming(self, entity_id):

        relationships = self._relationships()

        results = []

        for relationship in relationships:

            target_id = relationship[4]

            if target_id == entity_id:
                results.append(relationship)

        return results

    def get_neighbors(
        self,
        entity_id,
        relationship_type=None,
    ):

        relationships = self._relationships()

        neighbors = []

        for relationship in relationships:

            source_id = relationship[1]
            current_relationship = relationship[2]
            target_id = relationship[4]

            if (
                relationship_type is not None
                and current_relationship != relationship_type
            ):
                continue

            if source_id == entity_id:

                neighbors.append({
                    "direction": "out",
                    "relationship": current_relationship,
                    "entity_id": target_id,
                })

            elif target_id == entity_id:

                neighbors.append({
                    "direction": "in",
                    "relationship": current_relationship,
                    "entity_id": source_id,
                })

        return neighbors

    def traverse(self, root_entity_id, max_depth=3):

        visited = set()

        def walk(entity_id, depth):

            if depth > max_depth:
                return None

            if entity_id in visited:
                return None

            visited.add(entity_id)

            node = {
                "entity_id": entity_id,
                "neighbors": [],
            }

            for neighbor in self.get_neighbors(entity_id):

                child = walk(
                    neighbor["entity_id"],
                    depth + 1,
                )

                if child is None:
                    continue

                node["neighbors"].append({
                    "relationship": neighbor["relationship"],
                    "direction": neighbor["direction"],
                    "node": child,
                })

            return node

        return walk(root_entity_id, 0)
```

## One important correction before you proceed

Your current `NetworkGraph` and the new `MachineGraph` both call:

```python
self.store.all_relationships()
```

every time they search.

That's perfectly acceptable **for now**, because we're learning and building the architecture.

Later, when Galaxy has thousands or millions of relationships, repeatedly loading the entire relationship table will be inefficient.

We can eventually change this to database-level queries or build an indexed in-memory graph.

**Do not optimize that now.**

The immediate goal is:

```text
13A  Generic relationship navigation
 ↓
13B  Generic graph traversal
 ↓
13C  Test service → process → port
 ↓
13D  Keep ProcessTree/NetworkGraph as specialized views
```

Once those tests pass, **Milestone 13 is genuinely complete** and we can move to the next architectural layer rather than adding random collectors.
